**Reader** turns Chinese and English Markdown into a book you can actually read: chapter navigation, reading progress, selection highlights, notes and tags, multi-book switching, and online uploads, all in the browser. **No backend, no account, deploy and use.**

## Features

| Feature | Description |
|---|---|
| **Bilingual reading** | Single-column Chinese, single-column English, or side-by-side comparison with synchronized scrolling |
| **Chapter navigation** | Automatically generated TOC with current chapter highlighted while scrolling |
| **Reading experience** | Font size adjustment, three themes (light / eye-care / dark), and a top reading progress bar |
| **Select to annotate** | Select any text to highlight or write a note, including cross-paragraph selections |
| **Tag management** | Add tags to notes, filter by tag, and pick from existing tags with one click |
| **Batch delete** | Select multiple notes and delete them in bulk after confirmation |
| **Local persistence** | Notes are saved to browser IndexedDB, with JSON export / import |
| **Multi-book management** | Built-in book plus online upload of zip / folder, switch anytime |
| **Zero backend** | All logic runs in the browser, ready to deploy |

## How it works

| Step | What happens |
|---|---|
| **Load manifest** | Read `content/manifest.json` to get chapter order and titles |
| **Render chapters** | `fetch` the Markdown paths from `zh` / `en` in the manifest and render them into the page |
| **Reading aids** | Generate the TOC automatically, highlight the current chapter while scrolling, and show a top reading progress bar |
| **Save notes** | After selecting text, locate it with `TextQuoteSelector` (context + offset) and store it in IndexedDB |

## Quick start

### Run locally

**Option 1: Python built-in server**

```bash
cd project-root
python3 -m http.server 8080
```

Visit `http://localhost:8080`.

**Option 2: VS Code Live Server**

Right-click `index.html` and choose **Open with Live Server**.

> **Note**: Do not open `index.html` by double-clicking it. Under the `file://` protocol, `fetch` is blocked by browser CORS and the page will fail to initialize.

### Deploy to GitHub Pages

| Step | Action |
|---|---|
| **1. Push code** | Push the code to a GitHub repository (Public) |
| **2. Enable Pages** | Repository Settings → Pages → Source → **Deploy from a branch** |
| **3. Choose branch** | Branch: `main`, folder: `/ (root)`, then Save |
| **4. Wait** | Wait 1-2 minutes, then visit `https://<username>.github.io/<repository>/` |

> **Note**: All resource paths in the code are relative (no leading `/`), so the project can be deployed directly under a subdirectory. If you later add files that reference absolute paths, they will 404 under GitHub Pages.

It is recommended to add an empty `.nojekyll` file at the repository root to prevent GitHub Pages from ignoring certain directories when processing with Jekyll:

```bash
touch .nojekyll
git add .nojekyll
git commit -m "chore: disable jekyll"
git push
```

## manifest.json format

`content/manifest.json` defines chapter order and titles:

```json
{
  "title": "FDE - The Guidance Book",
  "chapters": [
    {
      "id": "ch01",
      "titleZh": "Chapter 1 - What is an FDE",
      "titleEn": "Chapter 1 - What is an FDE",
      "zh": "content/zh/ch01.md",
      "en": "content/en/ch01.md"
    }
  ]
}
```

| Field | Description |
|---|---|
| `id` | Unique chapter identifier, recommended to use the file name (without `.md`) |
| `titleZh` | Chinese title |
| `titleEn` | English title |
| `zh` / `en` | Paths relative to the book root (for the built-in book, relative to the project root) |

Chapters are displayed in the order of the `chapters` array.

### Generate with the tool

If you do not want to write the manifest by hand, open `tools/manifest-generator.html`:

1. Drag the book folder (containing `zh/` and `en/` subdirectories) into the page
2. The tool automatically pairs Chinese and English files and reads each `.md` H1 as the title
3. In the preview table, you can edit the ID, Chinese title, and English title
4. Click "Download manifest.json" to get the file
5. Overwrite `content/manifest.json` in the project (or let the tool handle it automatically when uploading a book)

> It is recommended to review the generated file manually, especially the titles and chapter order.

## Upload a book

After deployment, click the **📚+** button in the toolbar:

| Method | Description |
|---|---|
| **Choose zip** | Compress the book folder into a zip and upload it |
| **Choose folder** | Directly select a folder containing `zh/` and `en/` subdirectories |

If the folder contains `manifest.json`, it is used directly; otherwise, the tool automatically generates one from the `.md` files under `zh/` and `en/`.

Uploaded books are stored in browser IndexedDB and are only visible in your current browser; they are not pushed to GitHub. Switch books using the dropdown selector on the left side of the toolbar.

## Data storage

All data is stored locally in the browser:

| Data | Storage location | Description |
|---|---|---|
| Notes | IndexedDB `notes` | Includes highlights, notes, and tags |
| Uploaded books | IndexedDB `books` + `bookFiles` | Stored independently per book |
| Settings | localStorage `fde-settings` | Font size, theme |
| Last reading position | localStorage `fde-last-book` / `fde-last-chapter-*` | Restored on next open |

**No cross-device sync.** To migrate, use the export / import JSON feature in the notes panel.

> **Warning**: Clearing browser data (site data) will also clear notes and uploaded books. Export backups regularly.

## Browser compatibility

Recommended: **Chrome / Edge 105+, Safari 17.2+, Firefox 140+**

| Capability | Implementation / fallback |
|---|---|
| Highlights | CSS Custom Highlight API; older browsers fall back to `mark` (cross-paragraph selections may fail) |
| Folder upload | `webkitdirectory`, supported by modern browsers |
| Zip extraction | JSZip (loaded via CDN) |

## Known limitations

- Note highlights are located using `TextQuoteSelector` (context + offset). If the body text is modified, highlights may become invalid (the notes themselves are not lost)
- Uploaded books cannot be renamed (not implemented yet). To change the name, delete and re-import
- Tags are free text and are not deduplicated or merged (tag management may be added later)
- Batch delete is a hard delete, with no recycle bin

## Additional notes

- Uploaded books and notes are stored **locally in the browser**. Switching browsers or clearing cache will lose them. It is recommended to keep exported JSON in cloud storage.
- If you later want "uploaded books to be pushed to GitHub so others can see them", you need to go through git commits (put the book in the `content/` directory and update the manifest). Online upload only solves "local preview" and does not change server content.
- After deploying to GitHub Pages, the content in `content/` updates with the repository, but **books uploaded by users only take effect in their own browser** and will not be visible to others. This is an inherent limitation of pure front-end applications. If you want multi-user book sharing, you need a backend.
